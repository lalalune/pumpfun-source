# Pump Main v2 trades: SharingConfig shareholder list in the TradeEvent, original vs rebuild (2026-10-30)

## Question

Native-SOL `buy_v2` / `sell_v2` take a `sharing_config` account. Its address
is constrained to the pump_fees PDA `[b"sharing-config", mint]`
(`buy_v2.rs:158`, `sell_v2.rs:61`). The handler reads it with
`sharing_config_shareholders` (`util/payments.rs:28-31`):

- empty data -> `None`;
- `SharingConfig::try_deserialize` error -> `None`;
- otherwise the shareholder vector.

The vector is copied into the TradeEvent, which is emitted twice (`emit!` +
`emit_cpi!`).

No earlier Pump Main packet sets a SharingConfig on a trade. This packet
measures, on both images:

- how CU and event size scale with the shareholder count n;
- where the 32 KiB heap runs out;
- how malformed SharingConfig data is treated;
- that the address constraint holds.

**Reachability:** pump_fees caps the list at 10 (`TooManyShareholders`,
`programs/pump-fees/src/sharing_update.rs:138/286/516`,
`update_fee_shares*.rs`). Only pump_fees can write the PDA. Lists with
n > 10 and the malformed or system-owned variants are therefore **synthetic
states**. They measure the code path, not a reachable mainnet condition.

## Setup

- LiteSVM (solders 0.27.1). Pump runs under the upgradeable loader.
- The pump_fees slot holds a 9-instruction SBPFv0 stub generated by
  `producer.py`. It returns fees (0, 95, 30) bps and is identical for both
  images.
- Every trade is 10^9 tokens on the default curve. SharingConfig is built
  from the pump_fees IDL layout: disc | bump | version | status | mint |
  admin | admin_revoked | vec<Shareholder{pubkey, u16}>.
- Synthetic state, fixed keys and clock, one fresh VM per case. The full state
  is in `runtime/plan.json.gz`.

## Result

**36 cases. 0 behavior mismatches.** Error, events, inner instructions,
after-state and tx bytes are equal on every case. CU differs on 35/36 cases.
Each of those differs only in its `consumed` line, by a constant -2 (buy_v2
success) or -3 (sell_v2, and buy_v2 out-of-memory). That is the same
creator-fee-branch offset that `pump-trade-cu-scaling-20261030` attributes.
It does **not** change with n.

- **Event size is exactly 390 + 34·n bytes** (buy_v2; sell_v2 is 1 byte
  longer) on both images.
- Within the reachable range (n <= 10), each added shareholder costs between
  423 and 526.5 CU (0->1: 468; 1->2: 423; 2->4: 1,053; 4->8: 1,698;
  8->10: 846). Absent -> 10 shareholders is +4,687 CU on both buy_v2 and
  sell_v2. An empty but present SharingConfig costs +199 over an absent one.
- **Heap exhaustion is the same on both images.** The log reads
  `Error: memory allocation failed, out of memory`, then `SBF program
  panicked`, giving `ProgramFailedToComplete`. buy_v2 fails from n = 64 and
  sell_v2 from n = 96. At 64/96 the first `emit!` log line is written before
  the failure. At 128 the failure comes before any event.
  The boundaries were not bisected below these points.

### 2. Malformed data and the address constraint

| case | result | event bytes | CU orig / rebuild |
|---|---|---:|---|
| `malformed/buy_v2/bad-discriminator` | success, no shareholders | 390 | 95,915 / 95,917 |
| `malformed/buy_v2/declared-5-has-4` | success, no shareholders | 390 | 96,268 / 96,270 |
| `malformed/buy_v2/status-2` (enum out of range) | success, no shareholders | 390 | 96,120 / 96,122 |
| `malformed/buy_v2/admin-revoked-2` (bool 2) | success, no shareholders | 390 | 96,157 / 96,159 |
| `malformed/buy_v2/discriminator-only` | success, no shareholders | 390 | 95,881 / 95,883 |
| `malformed/buy_v2/declared-u32-max` (vec len 2^32-1, no data) | success, no shareholders | 390 | 96,009 / 96,011 |
| `malformed/buy_v2/trailing-100-bytes` | success, 4 shareholders | 526 | 97,506 / 97,508 |
| `malformed/buy_v2/owner-system-valid-data` | success, 4 shareholders | 526 | 97,506 / 97,508 |
| `malformed/sell_v2/bad-discriminator` | success, no shareholders | 391 | 84,893 / 84,896 |
| `address/buy_v2/not-the-pda` | ConstraintSeeds | - | 51,524 / 51,524 |

- Every deserialize error degrades to "no shareholders", and the trade still
  succeeds.
- A vector length of u32::MAX with no data does not trigger a large
  allocation (96,009 CU).
- The account owner is not checked: valid data on a system-owned account at
  the PDA is parsed. Because the address must be the pump_fees PDA, only
  pump_fees can create data there.
- A valid SharingConfig at any other address stops at ConstraintSeeds on both
  images, with the same CU.

## Reproduce

```
python3 producer.py --root <repo> --images '{"original": "<repo>/evidence/original/pump/deployed.so", "candidate": "<candidate.so>"}' --out <dir>
python3 verify.py --images '{"original": "<deployed.so>", "candidate": "<candidate.so>"}'
```

`producer.py` reads only `evidence/upstream/pump.json`, to check
discriminators. Two runs give byte-identical runtime files. `verify.py` uses
only this folder and the two images. It checks the image sha256 values,
replays all 36 cases on both images, compares every receipt byte for byte
and recomputes the summary. It exits 0 on success.

## Overlap
