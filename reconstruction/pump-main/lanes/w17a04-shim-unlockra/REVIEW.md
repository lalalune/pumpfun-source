# Reconstruction review

The accepted candidate preserves the existing owner-load shim and improves the remaining CTO token ratio from 0.67466 to 0.67615 at 27,400 bytes. All 1,034 raw and normalized matched windows remain matched. Relative to the fresh preceding main build, exactly 18 executable bytes change, all stack-reference offsets inside CTO. The six-offset map describes the changed spill references; other lifetimes reuse those physical words, so this is not a global stack-permutation proof.

The private `rcinc` helper is conditional on the concrete live default-Global `Rc<RefCell<&mut u64>>` used here and the pinned 64-bit identity toolchain. The shipped Rc allocation has a `Cell<usize>` strong counter first; the actual target probe has Rc size/alignment 8/8 and a zero-sized Global allocator. Stock clone and the helper load that allocation pointer, assume a nonzero strong count, increment/store, and trap on overflow. Only branch metadata differs. `Cell` permits the interior counter write; the pointer retains its allocation provenance, and the copied Rc is balanced by the preceding increment. This is an implementation-specific layout dependency, not a public Rc layout guarantee or historical source attribution.

Fresh signed synthetic comparisons cover 388 independent cases and nine persistent lifecycle cases with 20 transactions per image. Both suites pass; their finite scope does not establish complete semantic equivalence. A single alternative using public `Rc::strong_count` and `clone` was tested and excluded because it lost 687 raw windows.
