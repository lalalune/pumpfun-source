This reconstructs **303599.Q/j/G/o**: the capped viewer-following query, strict
array/error guards, case-folded membership Set, active state and passive cache
observer. These behaviors were previously available only inside an inert
factory. The adapter requires a website-client-shaped transport and externally
supplied viewer/query state; it creates no session or query engine.

## Request and decoding

`viewerFollowingQueryOptions(transport, viewerKey)` uses raw key
`['viewer-following', viewerKey]`, 60s stale time, 300s GC time and refetch on
window focus only for query status `error`. Other query-runtime defaults remain
external. A valid query context with a falsy viewer returns an empty array
without HTTP. The callback still destructures the context, as in the source.

Otherwise it sends `GET /following/v3/following/{userId}` with limit **1000**,
the exact signal, `throwHttpErrors: false`, response hook and parseJson override.
The hook throws a **plain Error** for any non-OK status, before reading the body.
A cloned successful blank body throws shared `UserFetchError('empty_body')`.
The parser catches native JSON failures as `invalid_json` and rejects non-array
JSON as `invalid_shape`. It preserves individual raw rows. An additional
post-transport null guard is retained; no broader callback sanitizer is invented.

This is one capped page. It adds no offset loop, total, continuation or complete
graph guarantee. A false membership result means absent from the supplied
successful Set, not an independently verified complete graph.

## Active, passive and unknown

The Set indexes nonempty string address and then `user_id ?? userId`, folding
case without trimming. Empty or nonstring legacy IDs suppress the newer field
when non-nullish. Rows and identities are not normalized into another DTO.

| Boundary                 | Enablement                                 | Membership result                                                                 |
| ------------------------ | ------------------------------------------ | --------------------------------------------------------------------------------- |
| Active options/state     | `(options.enabled ?? true) && !!viewerKey` | Boolean only when enabled and query.isSuccess; otherwise undefined                |
| Passive options/observer | Query options force enabled:false          | Boolean only with viewer, target and successful cached query; otherwise undefined |

`viewerFollowingState` preserves the query's error flag and exposes the Set even
while unready. It does not turn stale cached membership into a known result on a
failed/loading query. The passive observer can consume successful cache without
starting a read. Disabled options are query-runtime behavior, not authorization;
their callback still exists and can be invoked manually by a host.

The Set is the same mutable object captured by the active membership function,
as in the source. React Compiler Set/callback memo reuse and TanStack scheduling
remain outside these plain state boundaries. Malformed cached non-array data
retains its source iteration failure rather than silently becoming empty.

## Verification and limits

From `app`:

```sh
node scripts/original-viewer-following.mjs --check
node --test tests/original_viewer_following.test.mjs \
  tests/original_profile_lookup.test.mjs
```

Fifteen novel tests authenticate source/dependency/ranges and reject capture
tampering; exercise strict decoding, raw keys, exact signal, empty-viewer guard,
legacy ID priority, case/whitespace rules, active/passive readiness and unknown
membership. Three loopback HTTP scenarios cover encoded capped GETs through
membership projection, status/blank/JSON/shape failures, and exact cancellation.
The test transport uses native fetch/Response and explicit hook/parser order;
it is not captured Ky, a browser cookie jar or a production fixture.

No production request, server, mutation, auth/provider, UI mount, feature-ledger
milestone or API compatibility qualification is included. Test rows are local
synthetic inputs. Full Next build/browser validation was not run on this head;
aggregate qualification remains separate. The receipt records exact tested
file hashes, maintained base, accepted dependency blobs and commands.
