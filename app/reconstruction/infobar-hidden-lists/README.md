# Original ordinary InfoBar hidden lists

This recovers the complete ordinary token/profile hidden-list field workflow: both actual `124884.en` renderers, full accessible keyed `L` chip list and newest-first sorters, their actual `807786` device-setting descriptors, and the used `551792` value/coercion/key helpers plus `605587.c` identifier case rule. It supplies editable UI, admitted synthetic value normalization, exact local callback shape and descriptor wiring without inventing private preference storage or account acquisition.

Four authenticated physical factory contexts supply 14 complete AST regions, each retained exactly once inside its used exported constructor. Ten raw witnesses bind the actual custom-control dispatcher, existing local framework's coerce → write call, descriptor imports and formatting ports. The generator authenticates raw capture/index/range hashes with the shared source reader and parses bundles as data; it never evaluates a captured factory.

The exports are:

- `createHiddenInfoBarValues()` returns the exact token/profile coercers and key functions. Entries require nonempty string mint/address, string symbol/username falls back to empty, and nonfinite `hiddenAt` falls back to zero. Oldest-first selection retains the newest 200 **before** canonical-key collapse. Object overwrite/insertion order is preserved. Tokens preserve mint whitespace, while profile keys trim; only the literal lower-case `0x` prefix causes lowercasing. These are original value rules, not chain-address validation or a strict API schema.
- `createHiddenInfoBarDefinitions({values,store,makeBucketAdapter})` returns the two complete source device descriptors. The supplied original-compatible bucket builder receives `{store,select,write}`; each write calls the supplied state's `setField` for its own field. It does not create/read a store or implement persistence.
- `createHiddenInfoBarFields(capabilities)` returns `HiddenTokens` and `HiddenProfiles`, accepting `{definition}`. Supply actual React/compiler/JSX, `useSetting(id) → [value,setter]`, `readSetting(id)`, translation, Row/Action/CloseIcon, display normalization, profile-label and address-abbreviation capabilities, and the exact value helpers. Returned renderers retain all original label/empty/note/clear/chip branches. Unhide passes a function to the latest-value setter; clear passes `{}`. Token empty text intentionally also depends on whether local hidden profiles is empty.

The label helpers remain explicit compatible ports: `formatProfileLabel({address,username: username || null})`, `truncateAddress(mint,4,4)`, and `normalizeDisplayText(text,"coin-symbol"|"user-name")`. No profile lookup, native Unicode/label algorithm or media acquisition is inferred. The complete chip buttons preserve their actual aria-label, key, callback ID and close-icon props.

Attribution: #1839 already recovers the exact local setting framework; #1872 covers the field dispatcher; #1920 recovers row/section frames; #675/#683 retain metadata/context. They remain external capabilities, without copied/unmerged runtime imports or retally. Existing InfoBar keyboard shortcuts and native Settings fixes are unchanged. The entire `551792` store's mode/watchlist/PnL/positions/other fields, `628127` persistence, whole InfoBar/Settings mounting and private availability acquisition are outside this unit. Only two ordinary hidden-list descriptors are returned; excluded controls are not exposed.
