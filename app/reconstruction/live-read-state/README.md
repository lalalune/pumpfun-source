## Deliberately preserved behavior

- Hero query key contains NSFW but **omits IPFS**, while its query function
  depends on both. Section key includes sort, NSFW, nominal limit and IPFS.
  Nominal limit defaults to24; #1821's actual most-viewers request can force100.
  No key/request consistency fix or cache behavior is invented.
- Hero memo frame10 returns the query result directly. Section frame21 seeds
  initial data by truthiness (empty arrays still create page zero), defaults
  staleTime to10000 only for undefined, keeps original pager/selector identities,
  memoizes ordered flattened rows and returns only five source fields. Query
  errors do not create a new returned error field or error UI.
- Main completed-section state is a one-way Set. Not-loading completion fires
  even for empty data and can unlock the next section. First two sections are
  eager; later unlocked sections wait for intersection. The gate persists its
  seen state, uses actual `300/2 =150px` root margin and disconnects on admission
  and effect cleanup. Leaving the viewport does not revoke seen admission.
- Section loading renders the skeleton; empty data renders null. The source
  near-end callback invokes `fetchNextPage` only with `hasNextPage` and without
  an in-progress fetch, and does not return/await that promise. Its optional
  completion callback runs from the actual loading/key/callback-dependent effect.
- Show-all uses the actual truthy callback and four-card/next-page test. The
  supplied `onShowAll` callback is used as that truthy input; rendering supplies
  the actual link. Expanded/eager/viewport flags pass to the row-renderer port.
- Geographic/disabled-feature input selects the original blocked rendering
  branch; it does not establish real geographic eligibility or backend access.
