# Public incentive schedule context

The existing public Pump activity record shows stored user counters and explains
that the SDK's incentive routines also require a separate Global record. The
integrated **Read public incentive schedule** action now inspects that public
program-wide record independently. Loading the page, reading the user record or
connecting a wallet does not trigger this lookup.

The unchanged published SDK provides the fixed Global PDA and actual decoder.
Its IDL describes a 544-byte prefix: a discriminator, three signed 64-bit schedule
values, a mint public key and two arrays of 30 unsigned 64-bit values. The reader
checks mainnet identity, account owner, discriminator, bounded canonical base64,
account size and context before decoding. The view preserves all integers as exact
decimal strings. Missing records remain missing; invalid layouts and provider
failures show an unavailable state without old or estimated values.

The table supplies context for the separate user record. It does not invoke
`totalUnclaimedTokens` or `currentDayTokens`, interpret timestamps as an active
campaign, validate the economic meaning of a mint, calculate payouts, establish
eligibility, sum token units, or enable a claim. Global/user/balance reads can
observe different slots. No address, cookie or user identity is sent to the fixed
Global endpoint, and no wallet connection, signature or persisted state is used.

## Source and boundaries

`scripts/global-incentive-record/contract.mjs` authenticates six SDK source files
against the captured npm archive, derives the fixed account layout/PDA and records
five exact AST witnesses. Generated output is under
`research/global-incentive-record-20261029/SOURCE.json` and the module's
`contract.json`. Neither the SDK sources nor published package adaptations change.
This is an independent public read, not an original website/backend API claim.
It adds no feature-score or native-operation completion claim.

`GET /api/portfolio/incentive-record` accepts no query arguments. It uses the
existing pinned mainnet RPC service and only the existing `getGenesisHash` and
`getAccountInfo` reads. `HEAD` performs the same guarded read with an empty body.
Responses are `no-store`; provider details remain hidden. The browser explicitly
omits credentials, validates the fixed account and exact field widths, aborts on
unmount, and uses a finite deadline. Refresh clears the previous record first.
