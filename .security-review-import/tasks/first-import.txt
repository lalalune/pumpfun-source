L-14 — Fees funding accounts are readonly in generated metadata
Evidence
ExtendFeeConfig.user is a Signer without mut: programs/pump-fees/src/contexts.rs:8-15, yet extension transfers rent from it at programs/pump-fees/src/instructions/admin/extend_fee_config.rs:65-76.
ClaimSocialFeePdaV2.social_claim_authority is also readonly: programs/pump-fees/src/social.rs:119-132.
The token-claim branch passes that signer as the ATA-creation payer: programs/pump-fees/src/social.rs:21-29; the payer funds the associated-token instruction at programs/pump-fees/src/instructions/fee_sharing/mod.rs:259-292.
Failure statement
Default generated instruction metadata omits writability needed when extension requires additional rent or a social-fee claim must create the recipient ATA. Those otherwise valid operations can fail writable-privilege checks. Manually marking the payer writable avoids the defect; this is integration availability impact, not an authorization bypass.
M-14 — Creator-fee distribution overflows before division
Evidence
Native distribution computes available.checked_mul(share_bps)? / 10000: programs/pump/src/creator/distribute_creator_fees.rs:121-168, especially line 165.
Token distribution performs the same u64 intermediate multiplication using the entire source balance: programs/pump/src/creator/distribute_creator_fee_v2.rs:145-176, especially line 168.
Failure statement
A balance above u64::MAX / share_bps reverts even when the mathematically correct payout fits in u64. For a 10,000-bps recipient, 10^18 base units should pay out 10^18, but the intermediate multiplication overflows. High-decimal token vaults can reach this through ordinary accumulation or unsolicited transfers, leaving distributions unavailable through the affected instruction.
M-16 — Permissionless foreign-mint claims poison AMM cashback counters
Evidence
ClaimCashback.user does not sign, and quote_mint has no recognized-cashback-mint constraint: programs/pump-amm/src/instructions/token_incentives/claim.rs:147-177.
The entire selected accumulator ATA balance is transferred and added to shared total_cashback_claimed with checked addition: programs/pump-amm/src/instructions/token_incentives/claim.rs:210-228.
The counter is a single u64, not per mint: programs/pump-amm/src/state/volume_accumulator.rs:26-36.
Anyone can initialize the victim’s accumulator: programs/pump-amm/src/instructions/token_incentives/init_user_volume_accumulator.rs:9-22.
Failure statement
For victim counter C, an attacker can mint u64::MAX - C units of a worthless token, fund the victim accumulator’s ATA for that mint, and permissionlessly claim it to a victim-owned token account. The shared counter becomes u64::MAX; every later positive genuine cashback claim overflows and reverts. Closing and recreating the accumulator resets the counter but can forfeit pending incentive rights under L-06. This is repeatable targeted griefing, not cashback theft.

The accounting defect is confirmed:
Legacy migration reads the entire post-transfer base ATA balance and seeds with it: programs/pump/src/migrate.rs:250-284.
V2 does the same for base while measuring quote by received delta: programs/pump/src/migrate_v2.rs:249-327.
However, the current HIGH attack path does not establish a profitable donor round trip. In the fee-free constant-product model with fair initial reserves (B,Q) and donation D, let s = sqrt(1 + D/B). A donor who also performs the arbitrage that restores the original price has net value change:
-2Q(s - 1) < 0, before fees.
An independent arbitrageur can profit, but the donation subsidizes that arbitrage and the pool; it does not give the donor a demonstrated profitable extraction path. The supported impact is therefore initial-price disturbance and violation of exact-seed accounting, not HIGH-severity theft or drainage.
