Launchpad contract security audit and remediation

**Date:** 2026-10-30
**Release assessment: DEPLOYMENT STILL GATED.** All five programs now build for the real SBF target with no stack-frame diagnostics. Source-derived CPI interfaces, historical reward preservation, and additional deployment defects have been repaired. The current evidence includes 49 full-program host tests, 80 focused checks, and eight SVM lifecycle cases. This is bounded acceptance; the remaining address, setup, funding, trading-route and Relay/Jupiter gates below still prevent unconditional release approval.

The review covered all five programs and local support crates in parallel: Main, AMM, Fees, Donation Relay, and Mayhem. The original baseline contains 227 Rust files / 40,543 lines. Reviews traced exported instructions, account ownership/PDA/signer constraints, initialization, authority changes, CPI boundaries, token extensions, arithmetic, trading, migration, donations, payouts and rewards. Unlinked models were distinguished from executable handlers.

The original detailed findings are preserved in [the baseline report](audit/remediation-20261030/SECURITY_REPORT.baseline.md). Its original counts and statements that no code was patched are historical, superseded by this report. **“Patched” below means a source repair with the stated focused evidence; it does not mean a successful complete on-chain acceptance test.**

## Highest-impact findings

### C-01 — Permissionless pre-created ATAs can indefinitely block Relay principal settlement

**CRITICAL impact; source-confirmed, underlying SPL behavior reproduced; complete Relay transaction verification still pending.**

The original close-epoch instruction initialized a deterministic distribution ATA with non-idempotent creation. Anyone could create that valid ATA first without the distribution PDA's signature. Normal ATA creation then rejected it, so epoch closure rolled back and the tracker could not advance. Both swap instructions had the equivalent problem with the deterministic output ATA. The relevant state had no user-callable recovery route. A program upgrade was a possible remedy; this was a freeze of targeted buckets, not theft or an assertion that every asset was frozen automatically.

**Patch:** the three token-account initializations accept existing valid ATAs while retaining authority, mint and token-program constraints. Program-owned distribution/receipt state still uses one-time initialization. Actual balance/delta accounting handles nonzero pre-existing balances.

**Evidence:** the real SPL associated-token-account processor rejects ordinary Create on an existing valid ATA and accepts CreateIdempotent. Source account wiring is reviewed. See [Relay/Mayhem evidence](audit/remediation-20261030/relay-mayhem-summary.md).

Sources: `programs/donation-relay/src/instructions/v1/relayer_only/close_donation_epoch.rs`, `.../distribute/just_swap.rs`, `.../distribute/swap_then_distribute.rs`.

### C-02 — Unsolicited wrapped-native credits can freeze Relay swap settlement

**CRITICAL impact; source-confirmed, underlying SPL behavior reproduced; complete Jupiter/Relay transaction verification still pending.**

Originally, a swap had to spend exactly the recorded epoch total. Any unsolicited WSOL surplus remained afterward, and cleanup attempted to burn it. SPL Token rejects burning native accounts, reverting both swap settlement routes. Spending the surplus too instead violated the old exact-input invariant. No successful receipt existed for the alternative post-swap route, and direct non-swap settlement accepts only the fixed settlement mint. This froze that epoch's principal pending repair.

**Patch:** sync native balances before snapshots, require actual funds to cover the recorded amount, swap the actual input balance, and distribute actual output balances to the same beneficiaries. Exact input-spend and positive output-delta checks remain. Surplus goes to beneficiaries; the relayer must refresh its quote when balances change. Old Token-2022 withheld balances are harvested before cleanup where applicable.

**Evidence:** a real Token-2022 processor rejects native Burn and demonstrates SyncNative incorporating unsolicited lamports; production math tests validate balance coverage, received deltas and large amounts. Full swap-route execution remains an acceptance gate.

Sources: `programs/donation-relay/src/settlement_handlers.rs`, `src/cpi/jupiter.rs`, `src/settlement_math.rs`, `src/settlement_tokens.rs`, `src/tools/distribution/shared.rs`.

### H-03 / H-05 — First-caller takeover of Mayhem and Main administration

**HIGH; patched at the source boundary.** Both initializers previously let any signer become singleton administrator before legitimate initialization. They now bind the executable program to its upgradeable-loader ProgramData and require the current upgrade authority's signature. No guessed bootstrap key was inserted. Initializers fail closed after upgrade authority has been renounced; deployment must initialize before renunciation.

Main regression tests exercise actual Anchor Program, ProgramData and Signer wrappers: correct authority succeeds; attacker, nonsigner, mismatched ProgramData, forged owner, absent authority and nonexecutable program fail. Actual compiled SBF initialization now passes for Main and Mayhem. AMM initialization was hardened in the deployment review below and also has an actual SBF positive/negative authority check.

## Compatibility and release gates

- Regenerate clients from the committed source-derived CPI IDLs. All five complete SBF builds now pass; every generated instruction account list/discriminator is compared to compiled Anchor output. The generator deliberately omits automatic PDA-resolution hints; clients must supply real constrained accounts.
- Main/Mayhem initialization needs executable-program and ProgramData accounts plus the actual upgrade authority. Authority rotations require incoming signatures. Fees config initialization now uses its canonical global authority. Legacy buy global-volume accounts must be writable; Mayhem account forwarding was updated; its generated CPI writable flags are regenerated and checked against compiled metadata. Actual Mayhem trade-route acceptance remains required.
- Initialize valid incentive state through the authorized admin instruction before trading. Current reward accounting supports opted-in legacy native buys only. No arbitrary quote valuation policy was invented.
- Historical campaigns now use permanent archive PDAs. After expiry, archive the old campaign before replacing its schedule; append that archive to the admin update. A delayed user calls the new settlement instruction before another campaign can accrue volume. Archives cannot be closed. Clients must fund archive rent and keep reward vaults funded across all outstanding campaigns. See the [Main recipe](security/main/README.md) and [AMM recipe](programs/lalalune-amm/security-tests/REWARD_LIFECYCLE.md).
- Relay routes must quote actual synchronized input balances. Whitelisting no longer bypasses unsupported extension checks. Mint/freeze authority retained by an explicitly trusted whitelist issuer remains an issuer risk.
- Complete first-run configuration before enabling public trading: nonzero Main native/quote reserves, fee tiers, buyback recipients, admitted reward mint/vault and global volume accounts. Mayhem also needs a trader, positive duration, funded vault and its expected fee-whitelist setup. See the linked deployment reviews.
- Verify every hardcoded program ID, fixed Relay relayer key, quote mint and external integration against the intended new deployment. Ownership of those addresses was not established. Relay still binds whitelist initialization and every settlement to its compiled relayer key; ownership and an operational relayer must be established before accepting funds. No live authority, vault or chain state was changed. The original checkout’s concurrent cleanup edits were left untouched; security commits were isolated in a separate worktree and pushed to the private repository’s `main`.
- Complete full instruction/SVM tests for initialization, unauthorized accounts, aliasing, all trading/liquidity routes, reward lifecycle, migration, fee distribution, native/token conservation, Token-2022 edge cases, and Jupiter settlement. Check compute and stack limits on final release binaries, then independently review the pinned deployable build.

- **80 focused checks pass:** Main 22, AMM 29, Fees math 3, Fees harness 7, Relay 9, Mayhem arithmetic 6, Mayhem authority 4. These overlap some full-program helper tests and include program-ID tests. [Focused checks](security/run_checks.sh).
- **Eight SVM cases pass:** Main/AMM immutable archive → two later campaigns → delayed settlement → actual SPL Token and plain Token-2022 payout/conservation/replay checks; Main/AMM bootstrap; Fees initialization/configuration/query; Mayhem initialization/admin rotation. Each instruction is capped at 200,000 compute units. The suite uses real compiled programs and token binaries, with synthetic initial account balances and modeled signer flags. [Runtime evidence and scope](security/lifecycle-runtime/README.md), [runtime log](security/build-evidence/runtime-tests.log).
- [Dependency review](security/dependency-review.md) records known advisory coverage. A dependency scan does not replace source or runtime review.

**Hosted CI has not run.** The [GitHub Actions run for `c36825e`](https://github.com/lalalune/lalalune-source/actions/runs/41066343228) was rejected before starting any jobs because the account exceeded its maximum queued-job count. The workflow passes local `actionlint`; this is an external queue-capacity blocker, not a failed contract test. Clear queue capacity and complete a hosted run before claiming hosted acceptance.

Main and AMM agents independently cross-reviewed the lifecycle and deployment fixes. No on-chain deployment, live key rotation or funding occurred. Full trading/liquidity/migration and Jupiter/Relay transaction acceptance are not established by these checks. Runtime cases use known initial states; they do not constitute an exhaustive transaction-state search or prove control of deployment keys.

Automatic safety review previously stopped an agent during deeper Relay transaction-test work, citing possible cybersecurity risk. That blocked work was not retried; no full Relay/SVM or Jupiter acceptance is claimed.
